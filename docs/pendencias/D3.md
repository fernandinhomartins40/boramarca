# Pendências humanas — D3 (painel web do dono)

## 1. Publicar o painel com a API de produção

1. No build de produção de `apps/web`, definir `NEXT_PUBLIC_API_URL` com a URL pública da API
   (sem `/v1`). O painel chama a API direto do navegador.
2. Na API, incluir a origem do site (ex.: `https://boramarca.com.br`) em `CORS_ORIGINS`.
3. Entrar com o telefone do dono de um espaço real e conferir as cinco telas.

## 2. Código por SMS

O login do painel usa o mesmo código por telefone do app. Em produção ele só funciona depois de
contratado o provedor de SMS (ver `docs/pendencias/C5.md`, item 3.4). Sem ele a API responde
`OTP_UNAVAILABLE` e o painel mostra a mensagem de erro da API.

## 3. Conferir as ações do painel com dados reais

O painel já responde as decisões de qualquer profissional do espaço (rota do dono), remarca
arrastando um atendimento na visão Dia (ou pelo botão do próprio cartão, pelo teclado) e filtra
a lista de espera no servidor. Testado contra a API local com o seed
(`apps/web/components/painel/e2e-painel.mjs`, capturas em `apps/web/docs/capturas-d3/`).

1. Com um espaço real de dois ou mais profissionais, responder uma decisão de outra pessoa pelo
   painel e conferir que a mensagem chegou ao cliente certo.
2. Arrastar um atendimento para outro horário com "Avisar o cliente" marcado e conferir o aviso
   no WhatsApp. O arraste fica na coluna do mesmo profissional (a rota não troca profissional).

## 4. Excluir conta pelo site

`/excluir-conta` pede só códigos `delete_account`: um número sem conta recebe "Não existe conta
com este número" e nada é criado. Em produção, conferir com o SMS real que o primeiro código entra
na conta e que o segundo confirma a exclusão.
