# Pendências humanas — A1 (núcleo da API)

## 1. Provedor de SMS para o código de login

Sem provedor, a API em produção responde **503 `OTP_UNAVAILABLE`** ao pedir código (de propósito:
não descarta códigos em silêncio). Em desenvolvimento o código vai para o log e `123456` funciona.

Passo a passo:

1. Escolher o provedor (ex.: Twilio Verify, Zenvia, AWS SNS, Infobip). Conferir preço por SMS no
   Brasil e se exige cadastro de remetente/template.
2. Criar a conta, obter as credenciais e (se houver) aprovar o template:
   `Seu código Bora Marca: {{code}}. Vale por 10 minutos.`
3. Pedir ao agente da API que implemente `OtpSender` (`apps/api/src/modules/auth/otp.ts`) para o
   provedor e o ligue em `src/plugins/auth.ts` (hoje: produção sem provedor = `unavailableOtpSender`).
   As credenciais entram como variáveis de ambiente novas em `apps/api/.env.example`.
4. Testar com um telefone real em homologação.

## 2. Conta de revisão das lojas

Definir em produção `REVIEW_PHONE` e `REVIEW_OTP` (ex.: o telefone de demonstração da Marina,
`+5511900000001`, após `pnpm db:seed` no banco de produção, ou uma conta própria com dados de
exemplo) e informar ambos nos formulários das lojas.

## 3. Segredos JWT de produção

Gerar `JWT_ACCESS_SECRET` e `JWT_REFRESH_SECRET` distintos (48+ bytes aleatórios cada):
`node -e "console.log(crypto.randomBytes(48).toString('base64url'))"`.
