# Pendências humanas — C4 (Alexa)

O código da skill está pronto e testado (`packages/alexa`). Tudo abaixo depende de conta Amazon,
de um Echo de verdade ou de aprovação externa. Antes de começar: a API precisa estar publicada em
`https://api.boramarca.com.br` com as rotas `/v1/alexa/skill`, `/v1/alexa/oauth/authorize` e
`/v1/alexa/oauth/token` ligadas (onda 4).

## 1. Criar a skill no console

1. Entre em <https://developer.amazon.com/alexa/console/ask> com a conta Amazon do Bora Marca (crie
   uma conta de desenvolvedor se não tiver).
2. **Create Skill** → nome "Bora Marca", idioma principal **Portuguese (BR)**, tipo **Custom**,
   hospedagem **Provision your own** (não Alexa-hosted). Modelo: **Start from scratch**.
3. Copie o **Skill ID** (`amzn1.ask.skill....`) para `ALEXA_SKILL_ID` no ambiente da API.

## 2. Modelo de interação

1. **Build → Interaction Model → JSON Editor**.
2. Cole o conteúdo de `packages/alexa/skill/interaction-model.pt-BR.json` → **Save Model** →
   **Build Model**.
3. Nome de invocação: `bora marca`. O PDF usava "Agenda", mas a Amazon não aceita nome de uma
   palavra genérica; as frases ficam "Alexa, pergunte ao Bora Marca…" e "Alexa, diga ao Bora Marca
   que sim". Se mudar o nome, mude também `decisionAnnouncement` e `SPEECH.help` em
   `packages/alexa/src`.

## 3. Endpoint

1. **Build → Endpoint → HTTPS**.
2. Default Region: `https://api.boramarca.com.br/v1/alexa/skill`.
3. Certificado: **My development endpoint has a certificate from a trusted certificate authority**
   (o Caddy emite pelo Let's Encrypt).

## 4. Vínculo de conta

1. Gere um segredo: `openssl rand -hex 32`. Coloque no ambiente da API:
   `ALEXA_OAUTH_CLIENT_ID=alexa-skill` e `ALEXA_OAUTH_CLIENT_SECRET=<segredo>`.
2. **Build → Account Linking**: ligue "Do you allow users to create an account or link…".
   Desligue "Allow users to enable skill without account linking".
3. **Auth Code Grant**:
   - Web Authorization URI: `https://api.boramarca.com.br/v1/alexa/oauth/authorize`
   - Access Token URI: `https://api.boramarca.com.br/v1/alexa/oauth/token`
   - Client ID / Secret: os mesmos do passo 1
   - Authentication Scheme: **HTTP Basic** (o código aceita também credenciais no corpo)
   - Scope: `agenda`
   - Domain List: inclua os domínios que a página de login carregar (ex.: `boramarca.com.br`).
4. Confira as **Alexa Redirect URLs** que o console mostra: devem começar com
   `https://pitangui.amazon.com/api/skill/link/`, `https://layla.amazon.com/api/skill/link/` ou
   `https://alexa.amazon.co.jp/api/skill/link/` (lista em `ALEXA_REDIRECT_PREFIXES`). Se aparecer
   outra, avise para incluir.

## 5. Testar com um Echo de verdade

1. **Test → Development**. No app Alexa do celular (mesma conta Amazon), em Mais → Skills → Suas
   Skills → Dev, abra "Bora Marca" e **vincule** com o telefone de um profissional de teste.
2. Fale no Echo e confira a resposta em menos de 8 s:
   - "Alexa, abra o Bora Marca"
   - "Alexa, pergunte ao Bora Marca quantos clientes faltam" / "tem horário vago" / "quem é o próximo"
     / "alguém mandou mensagem"
   - Com uma decisão pendente: "Alexa, abra o Bora Marca" → ouça a pergunta → "sim".
   - "Alexa, diga ao Bora Marca que sim, para daqui 15 minutos" — **conferir** se a frase cai em
     `ResponderSimIntent` (veja em Test → Intent History / Device Log). Em português, a Alexa às vezes
     consome o "que" depois do nome de invocação; as amostras cobrem os dois casos, mas só o aparelho
     confirma. Se cair em `AMAZON.FallbackIntent`, acrescente a amostra que faltou e refaça o build.
3. Confira na aba Decisões do app que a decisão aparece como "Você, pela Alexa".

## 6. Voice Monkey (anúncio proativo)

1. Crie conta em <https://voicemonkey.io>, instale a skill Voice Monkey no app Alexa e vincule.
2. No painel do Voice Monkey, crie o **Speaker** do Echo do balcão e copie o **Device ID** (v3).
3. Em Dashboard → API, gere o **token v3** (tokens v2 não funcionam) → `VOICE_MONKEY_TOKEN`.
4. No cadastro do profissional, ligue o anúncio e informe o Device ID (`AlexaSettings`).
5. Crie uma decisão (ex.: mensagem de teste no WhatsApp) e confira se o Echo fala a pergunta.
6. **Antes de escalar:** confirmar com o Voice Monkey os termos para uso comercial e o limite mensal
   de requisições do plano (o PDF já alerta). Hoje o contrato guarda **um token global** e um
   dispositivo por profissional, o que exige os Echos de todos na mesma conta Voice Monkey. Se cada
   profissional usar a conta Voice Monkey dele (como o PDF sugere), o token passa a ser por
   profissional — isso muda `AlexaSettings` em `packages/shared` e precisa ser decidido.

## 7. Publicação e certificação

1. **Distribution**: preencha com os textos de `packages/alexa/skill/skill.json` (nome, resumo,
   descrição, frases de exemplo, palavras-chave, categoria Calendars & Reminders, só Brasil).
2. Ícones: 108×108 e 512×512 PNG a partir do kit (`Bora-Marca-Kit/03-icones/icone-512.png`; o de
   108 é redução do mesmo arquivo), publicados em `https://boramarca.com.br/alexa/` ou enviados no
   console.
3. Privacidade: `https://boramarca.com.br/privacidade` e termos `https://boramarca.com.br/termos`.
   Responda "usa informação pessoal: sim" (nome do cliente é falado).
4. Instruções de teste para o revisor: conta de demonstração (`REVIEW_PHONE`/`REVIEW_OTP`) com uma
   decisão pendente criada no seed, e as frases do item 5.
5. **Certification → Validation / Functional test** → **Submit for review**. Corrija o que a Amazon
   apontar e reenvie.
