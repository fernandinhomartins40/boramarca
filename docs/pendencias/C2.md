# Pendências humanas — C2 (Decisões, Conversas e notificações do app)

## 1. Instalar `expo-task-manager` e ligar a tarefa em segundo plano (Android, app fechado)

Sem ele, Sim/Não na notificação respondem quando o app está aberto ou em segundo plano com o JS
vivo (ouvinte `addNotificationResponseReceivedListener`). Com o app **fechado**, o Android só roda
JS por uma tarefa do `expo-task-manager` (docs.expo.dev, `registerTaskAsync`: "Only on Android, the
task also runs in response to a notification action tap when the app is backgrounded or terminated").
Esta onda não podia instalar dependências.

1. `cd apps/mobile && npx expo install expo-task-manager`
2. Em `src/features/notifications/`, criar `backgroundTask.ts` e importá-lo em `index.ts`:

   ```ts
   import * as TaskManager from 'expo-task-manager';
   import * as Notifications from 'expo-notifications';
   import { runDecisionNotificationTask } from './decisionNotifications';

   export const DECISION_NOTIFICATION_TASK = 'decision-notification-task';
   TaskManager.defineTask<Notifications.NotificationTaskPayload>(
     DECISION_NOTIFICATION_TASK,
     async ({ data }) => runDecisionNotificationTask(data),
   );
   Notifications.registerTaskAsync(DECISION_NOTIFICATION_TASK).catch(() => undefined);
   ```

3. Novo dev build (`expo prebuild` + `assembleDebug`), porque é módulo nativo.

**iOS:** ao tocar uma ação com `opensAppToForeground: false`, o sistema acorda o app em segundo plano
e entrega a resposta ao ouvinte. Conferir num iPhone com o app fechado (item 4).

## 2. Som curto do canal "Decisões"

O canal usa `aviso.wav` (o mesmo aviso do Modo Balcão, `assets/sounds/aviso.wav`). O arquivo só entra
no app se o plugin `expo-notifications` do `app.config.ts` listar o som:
`{ icon: ..., color: ..., sounds: ['./assets/sounds/aviso.wav'] }` (pedido ao dono do `app.config.ts`).
O Android não deixa trocar o som de um canal já criado: depois de incluir o som, **desinstale o
app** do aparelho de teste antes de instalar o novo build.

## 3. Registrar o aparelho para receber push (precisa de conta Expo/EAS e Firebase)

A API já envia push com a categoria `decision` e o canal `decisoes`. Falta o app mandar o token:
`Notifications.getExpoPushTokenAsync({ projectId })` depois da permissão concedida e `POST /devices`.
Isso pede:

1. Projeto no EAS (`eas init`) para ter o `projectId` (`extra.eas.projectId` no `app.config.ts`).
2. Android: projeto no Firebase, `google-services.json` e a credencial FCM V1 enviada ao EAS
   (`eas credentials`).
3. iOS: chave APNs da conta Apple Developer enviada ao EAS.
4. Camada de dados com `devices.register` (pedido ao agente D1; não existe domínio `devices` em
   `src/data`).

## 4. Testar as ações da notificação num aparelho

Com `EXPO_PUBLIC_DATA_SOURCE=mock`, num dev build:

1. Abra a aba **Decisões** → no cartão "Responder pela notificação", toque **Ativar** e aceite.
2. Ajustes → Menu de desenvolvimento → **Simular decisão nova**. Deve aparecer a notificação
   "Rafael quer horário hoje. Posso marcar às 16h50?" com **Sim** e **Não** (no Android, puxe a
   notificação para baixo para ver os botões).
3. Com o app em segundo plano, toque **Sim**: a notificação some e chega "Respondido — Pronto. Já
   avisei Rafael." A decisão aparece em Resolvidas como "Você, na notificação".
4. Toque no corpo de outra notificação: o app abre na aba Decisões com essa decisão no topo.
5. "Decisão nova a cada 20 s" liga/desliga a repetição (prompt 05).
6. Repita num iPhone (simulador serve para notificação local) e, depois do item 1, com o app fechado
   no Android.
